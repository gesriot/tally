# tally-cli

Консольный клиент Tally – программа `tally`. Работает с той же базой SQLite, что и приложение (`tally-store`). Команды выполняет слой приложения `tally-app` ([`../tally-app/README.md`](../tally-app/README.md)): здесь только разбор командной строки и вывод. Даты разбирает `tally-when` – как в быстром вводе (памятка: [`../tally-when/quick-entry-ru.md`](../tally-when/quick-entry-ru.md)).

```sh
cargo run -p tally-cli -- add Позвонить маме завтра
cargo build -p tally-cli --release   # target/release/tally (tally.exe в Windows)
```

Окно приложения – отдельная программа `tally-ui` (`cargo run -p tally-ui`).

## Команды

| Команда | Что делает |
|---|---|
| `tally add <ТЕКСТ>…` | Добавить задачу. Дата в конце текста – дата начала: «Купить хлеб завтра», «Отчёт в пятницу вечером», «Поездка 15 дек». Без даты – во «Входящие» |
| `tally list [СПИСОК]` | Показать список; без списка – «Сегодня» |
| `tally done <ЗАДАЧА>…` | Выполнить задачи; `-c`/`--cancel` – отменить |
| `tally move <ЗАДАЧА>` | Перенести на дату, в список, проект, раздел или область |
| `tally search <ЗАПРОС>…` | Найти задачи, проекты, области и теги (без учёта регистра и «ё») |
| `tally project <НАЗВАНИЕ>…` | Создать проект; `-a <ОБЛАСТЬ>` – в области |
| `tally area <НАЗВАНИЕ>…` | Создать область |
| `tally heading <НАЗВАНИЕ>… -p <ПРОЕКТ>` | Создать раздел в проекте |
| `tally undo` | Отменить последнее действие |
| `tally redo` | Повторить последнее отменённое действие |

Справка: `tally --help`, `tally <команда> --help`; версия: `tally --version`.

### `add`

| Параметр | Значение |
|---|---|
| `-w`, `--when <КОГДА>` | Когда начать: «завтра», «пт», «через 3 дня», «вечером», «в любое время», «когда-нибудь». С этим параметром текст задачи не разбирается: `tally add "Фильм «Завтра»" -w пт` |
| `-d`, `--deadline <СРОК>` | Крайний срок – день: «пт», «15 дек», «через 2 недели». «Вечером», «когда-нибудь» и прошедший день словами («вчера») – ошибка |
| `-p`, `--project <ПРОЕКТ>` | В проект |
| `--heading <РАЗДЕЛ>` | В раздел проекта (только вместе с `-p`) |
| `-a`, `--area <ОБЛАСТЬ>` | В область (не вместе с `-p`) |
| `-n`, `--notes <ТЕКСТ>` | Заметки |
| `-t`, `--tag <ТЕГ>` | Тег, можно несколько раз. Нового тега ещё нет – он создаётся |

Задача в проекте или области без даты – в «В любое время», как в Things.

### `list`

| Список | Русское имя | Что показывает |
|---|---|---|
| `today` | `сегодня` | «Сегодня» и «Вечер» |
| `inbox` | `входящие` | «Входящие» |
| `upcoming` | `планы` | «Планы»: семь дней с завтрашнего (пустой день – один заголовок), затем остаток месяца, месяцы, годы; «⚑ срок» – день крайнего срока, «– вечер» – задача или проект на вечер, только в строке начала, не в строке срока |
| `anytime` | `любое` | «В любое время»; « ★» – задача видна и в «Сегодня» |
| `someday` | `когда-нибудь` | «Когда-нибудь»: задачи и проекты |
| `logbook` | `журнал` | Закрытые задачи и проекты: ✓ – выполнено, ✕ – отменено |
| `trash` | `корзина` | Корзина |
| `projects` | `проекты` | Открытые проекты с ходом: «проект «Ремонт кухни» – 2 из 5» |

Перед `list` и `done` консоль создаёт наступившие календарные экземпляры повторяющихся задач и проектов. Правила настраиваются в окне Tally, а новые экземпляры записываются в общий журнал действий.

### `move`

| Параметр | Значение |
|---|---|
| `-w`, `--when <КОГДА>` | Новая дата или список: «сегодня», «завтра вечером», «в любое время», «когда-нибудь» |
| `--inbox` | Во «Входящие»: без даты, проекта, раздела и области |
| `-p`, `--project <ПРОЕКТ>` | В проект |
| `--heading <РАЗДЕЛ>` | В раздел – указанного проекта или текущего |
| `-a`, `--area <ОБЛАСТЬ>` | В область; задача уходит из проекта |
| `--no-project` | Убрать из проекта и области |
| `-d`, `--deadline <СРОК>` | Новый крайний срок |
| `--no-deadline` | Убрать крайний срок |

Параметры сочетаются: `tally move 3f9a2c -p "Ремонт кухни" --heading Покупки -w пт`. Задача из «Входящих», попавшая в проект или область без даты, переходит в «В любое время». Без параметров – ошибка.

Несовместимы (код 2, задача не меняется):

| Параметр | Нельзя вместе с |
|---|---|
| `--inbox` | `--when`, `--project`, `--heading`, `--area`, `--no-project` |
| `--project` | `--area`, `--no-project` |
| `--heading` | `--area`, `--no-project`, `--inbox` |
| `--area` | `--no-project` |
| `--deadline` | `--no-deadline` |

## Отмена и повтор

`tally undo` отменяет последнее действие, `tally redo` повторяет последнее отменённое. Действия – это `add`, `done` (и `done -c`), `move`, `project`, `area` и `heading`; `list` и `search` ничего не меняют и в журнал не попадают. Каждое действие отменяется целиком: `done` с несколькими задачами – одним шагом, `add` – вместе с тегами, которые он создал.

```text
$ tally move 9b5b2f -p Дача -w "через неделю вечером"
Перенесено: [9b5b2f] Купить плитку – чт, 26 ноября, вечер · Дача ⚑ вт, 15 декабря
$ tally undo
Отменено действие: перенос задачи «Купить плитку»
  [9b5b2f] Купить плитку – пт, 20 ноября · Ремонт / Кухня ⚑ вт, 15 декабря
$ tally redo
Повторено действие: перенос задачи «Купить плитку»
  [9b5b2f] Купить плитку – чт, 26 ноября, вечер · Дача ⚑ вт, 15 декабря
```

После «Отменено действие» и «Повторено действие» – строки задач, которые действие затронуло и которые остались в базе (задача, чьё добавление отменено, не показывается).

- Журнал действий хранится в базе (таблица `history`), поэтому `undo` работает в следующем запуске `tally` и видит действия других клиентов той же базы: журнал у базы один. Помнятся последние 100 действий.
- `undo` подряд идёт назад по журналу, `redo` – вперёд. Новое действие после отмены стирает отменённые: повторять их уже нельзя.
- Отмена возвращает записи ровно в то состояние, в котором они были до действия: проект, раздел, область, дату, «вечер», срок, статус, теги. Повтор – в то, которое действие оставило, без нового разбора дат: «завтра» остаётся днём, который был завтра в момент команды, а время выполнения – прежним временем `done`. Отмена добавления и создания удаляет запись совсем, а не в «Корзину»; повтор возвращает её с тем же номером и временем создания.
- Время правки при отмене и повторе идёт только вперёд: время команды, но не раньше последней метки записи, иначе на наносекунду позже.
- Команда, которая ничего не меняет (например, `tally move Отчёт --no-deadline` у задачи без срока), выводит обычный результат с кодом 0, но в базу не пишет: метка и журнал прежние, `redo` после неё повторяет отменённое. Так и на пределе меток (`Timestamp::MAX`): ошибку «время правки записи достигло предела» даёт только настоящая правка.
- Нечего отменять или повторять – ошибка (код 1): «нечего отменять», «нечего повторять».
- Перед записью каждая затронутая запись сверяется с тем, что оставило действие (время правки не сравнивается). Если запись с тех пор изменили или удалили в обход журнала – например, другая программа писала прямо в базу, – отмена отклоняется (код 1), и ничего не пишется: «ошибка: нельзя отменить перенос задачи «Отчёт»: задачу [3f9a2c] Отчёт за ноябрь изменили после этого действия». Запись, которую отмена удалила бы, не должна быть нужна другим: «нельзя отменить создание проекта «Ремонт»: на проект «Ремонт» ссылается задача [3f9a2c] Плитка». Ссылка, которую отмена или повтор восстанавливают или ставят заново, должна вести на живое вместе со всей цепочкой (раздел, его проект, область проекта): «нельзя повторить добавление задачи «Полить»: проект «Дача» в корзине», «… раздел «Кухня» теперь в проекте «Дача»», «… раздел «Кухня»: проект «Ремонт» в корзине». Пример с архивным разделом: «Плитку» перенесли из «Кухни» в «Ванную», «Кухню» убрали в архив – `undo` отвечает «ошибка: нельзя отменить перенос задачи «Плитка»: раздел «Кухня» в архиве» (код 1), потому что восстановил бы ссылку на архивный раздел. Ссылка, которую шаг не меняет, сохраняется: отмена `done` в том же разделе проходит, даже если раздел потом убрали в архив. Когда причину убрали, отмена или повтор проходят. Те же правила – у самих команд: `tally move Плитка --heading Ванная` у задачи закрытого проекта «Ремонт» отвечает «ошибка: раздел «Ванная»: проект «Ремонт» закрыт» (код 1) и ничего не пишет, а прежний раздел (`--heading Кухня`) и вынос задачи из проекта (`--no-project`) проходят и сразу отменяются: проект, который действие застало закрытым и доступность которого с тех пор не менялась (переименование и заметка не в счёт), отмене не мешает. Прежний проект или раздел по названию, даже закрытый или архивный, – успех без изменений, если нет доступного живого с тем же названием (живой раздел закрытого проекта доступным не считается): `tally move <UUID> --heading Кухня` у задачи в архивной «Кухне» выводит «Перенесено» с кодом 0. Причина отказа важнее предела меток: на `Timestamp::MAX` `--heading Ванная` в закрытом проекте отвечает «раздел «Ванная»: проект «Ремонт» закрыт».
- Отмена, повтор и проверки идут в одной транзакции записи: два одновременных `undo` отменят два разных действия.

## Как указать задачу

У каждой задачи в выводе есть номер в скобках: `[3f9a2c] Купить хлеб`. Номер – начало идентификатора задачи (UUID, 32 шестнадцатеричные цифры). Длина в выводе – наименьшая, при которой номера всех задач в базе различаются, но не меньше 6 цифр.

Аргумент `<ЗАДАЧА>` понимается так:

1. 4 и больше шестнадцатеричных цифр (дефисы не учитываются, регистр – тоже) – начало идентификатора. Ищутся все задачи, кроме удалённых; так можно указать и закрытую – `done` тогда сообщит, что она уже закрыта.
2. Иначе, или если по номеру ничего не нашлось, – часть названия задачи в работе, без учёта регистра и «ё». Задача в работе – та, что не в «Журнале» и не в «Корзине» по правилам `tally-core`: закрытая сама или через закрытый проект не в счёт. Название, совпавшее целиком, важнее частичных совпадений; если таких несколько, ошибка перечисляет только их.

Подходит несколько задач – ошибка со списком подходящих; ничего – ошибка «задача «…» не найдена». Номер стабилен: он не меняется при переносе и закрытии задачи, а длиннее становится, только когда в базе появляется задача с тем же началом.

Проекты, разделы, области и теги указываются названием целиком, без учёта регистра и «ё». Учитываются только живые записи: не в корзине, проекты – ещё открытые. Если живых записей с таким названием несколько (например, одноимённую восстановили из корзины), это ошибка (код 1) со списком подходящих – CLI не выбирает наугад и не создаёт ещё одну: «ошибка: областей «Дом» несколько:», затем строки «[3f9a2c1b] Дом». У раздела в счёт идут только те, в которые можно перенести задачу: в закрытом проекте две живые «Кухни» не дают ошибки: задача, которая и так в «Кухне» (например, архивной), остаётся на месте, а задача из другого раздела получает отказ «раздел «Кухня»: проект «Ремонт» закрыт». Номер в этих строках – не короче 8 цифр, а если у кандидатов совпадают и первые 8, он удлиняется до первого различия («[3f9a2c1b4] Дом», «[3f9a2c1b7] Дом»). Ничего не записывается.

Тег в корзине у задач не показывается; связь с задачей остаётся, и после восстановления тега пометка возвращается. `add -t` с названием тега из корзины создаёт новый тег.

## Значения

Пробелы по краям значений отбрасываются. Пустое значение или значение из одних пробелов – у названия, тега, проекта, раздела, области, «когда», срока, задачи или запроса – ошибка командной строки (код 2): «ошибка: пустое значение у --tag <ТЕГ>». Ничего не создаётся и не меняется. Заметки (`-n`) могут быть пустыми.

## Несколько клиентов сразу

С одной базой могут одновременно работать несколько `tally` (и позже – приложение). Команда, которая меняет базу, читает нужные записи, проверяет их и записывает изменения в одной транзакции записи SQLite (`BEGIN IMMEDIATE`); второй клиент ждёт её конца (до 5 секунд) и видит уже новое состояние. Строка журнала действий пишется в той же транзакции. Поэтому `move` не вернёт в работу задачу, которую только что закрыл `done`, – он сообщит «задача … уже закрыта»; два одновременных `add -t Работа` создадут один тег, а у задач будут разные ключи порядка. Время создания и закрытия записей – время команды. Время правки изменяемой записи – тоже время команды, но не раньше её прежнего времени правки: если запись уже правили с часами, ушедшими вперёд, новая правка встаёт на наносекунду позже. Метки других записей на это не влияют. `list` и `search` читают один согласованный снимок.

## База

Путь к базе выбирается так:

1. `--db <ФАЙЛ>` (в любом месте командной строки);
2. переменная окружения `TALLY_DB` – путь как есть, в том числе с байтами вне UTF-8 на Unix; пустая переменная – как незаданная;
3. `tally.db` в папке данных пользователя:

| ОС | Папка |
|---|---|
| Linux | `$XDG_DATA_HOME/tally`, обычно `~/.local/share/tally` |
| macOS | `~/Library/Application Support/Tally` |
| Windows | `%APPDATA%\Tally\data` |

Папка создаётся при первом запуске, база – тоже.

Пустое или целиком пробельное значение `--db` отклоняется с кодом 2. Пробелы в допустимом пути сохраняются.

## Сегодняшний день

«Сегодня» – дата по местному времени. Переменная `TALLY_TODAY=ГГГГ-ММ-ДД` задаёт её явно – для тестов и примеров; не дата – ошибка (код 1), пустая – как незаданная:

```sh
TALLY_TODAY=2026-11-19 tally list upcoming
```

## Коды выхода

| Код | Когда |
|---|---|
| 0 | Успех, справка, версия; поиск без результатов («Ничего не найдено») |
| 1 | Ошибка выполнения: задача не найдена или уже закрыта, неверная дата, нет проекта, нечего отменять или повторять, конфликт отмены, база не открывается |
| 2 | Неверная командная строка: неизвестная команда или параметр, нет аргумента, пустое значение, несовместимые параметры; `tally` без команды |

Результат – в стандартный вывод, ошибки – в стандартный поток ошибок, с префиксом «ошибка: ». Цвета нет.

## Пример

```text
$ export TALLY_TODAY=2026-11-19
$ tally add Позвонить маме сегодня
Добавлено: [99da1b] Позвонить маме – Сегодня
$ tally add Заказать ужин вечером
Добавлено: [383e3a] Заказать ужин – Сегодня, вечер
$ tally list
Сегодня – чт, 19 ноября
  [99da1b] Позвонить маме
Вечер
  [383e3a] Заказать ужин
$ tally done маме
Выполнено: [99da1b] Позвонить маме
$ tally done zzzz
ошибка: задача «zzzz» не найдена
```

## Тесты

```sh
cargo test -p tally-cli
```

Модульные тесты – разбор команд, поиск задач по номеру и названию, переносы, сроки, русская справка и ошибки `clap`. Интеграционные тесты запускают саму программу с базой во временной папке и `TALLY_TODAY=2026-11-19`:

- `tests/cli.rs` – вывод, коды выхода, `--db` против `TALLY_DB`;
- `tests/undo.rs` – отмена и повтор: приёмочный сценарий с переносом в другой проект, отмена `add`, `done` и создания, пустой журнал, конфликт;
- `tests/edge_cases/` – конфликты аргументов, поиск по названию, одноимённые записи и теги, «Планы»;
- `tests/concurrency.rs` – команды одновременно в нескольких потоках, у каждой своё соединение с базой: `done` против `move` одной задачи и параллельные `add` с одним новым тегом.

Запуск быстрого ввода на собранных `tally` и `tally-ui` (окно не нужно) проверяет скрипт: `python scripts/check-quick-add-startup.py target/debug/tally`.
