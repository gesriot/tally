# tally-ui – окно Tally

Окно Tally: списки, области и проекты, раскрывающаяся карточка задачи, перетаскивание, поиск, быстрый ввод, трей и напоминания. Только отображение и привязка к `tally-app`: правила и данные – ниже по стеку. Что умеет окно и как им пользоваться – в [руководстве](../../docs/user-guide.md).

## Запуск

```sh
cargo run -p tally-ui                                    # Skia (по умолчанию)
cargo run -p tally-ui --no-default-features --features femtovg
cargo run -p tally-ui -- --db /путь/к/tally.db           # своя база
```

База – та же, что у консоли `tally`, и ищется так же: `--db <ПУТЬ>` (или `--db=<ПУТЬ>`), иначе переменная `TALLY_DB` (пустая – как незаданная), иначе `tally.db` в папке данных пользователя (Windows – `%APPDATA%\Tally\data`, macOS – `~/Library/Application Support/Tally`, Linux – `~/.local/share/tally`). Поэтому окно и консоль можно держать открытыми одновременно: всё, что сделано в окне, видно в `tally list`, и наоборот (окно перечитывает базу после каждой своей команды и по F5).

`TALLY_TODAY=ГГГГ-ММ-ДД` подменяет сегодняшний день – для примеров и снимков экрана. Без неё день берётся из часов системы при каждой команде, так что после полуночи списки пересчитываются без перезапуска (при следующем действии или F5). Неверная дата в `TALLY_TODAY` – ошибка при запуске, а не молчаливые системные часы.

Пустой путь в `--db` (`--db=`, `--db ""`, путь из одних пробелов) – ошибка до открытия окна, код 2, как у неверных аргументов консоли: SQLite открыл бы вместо него временную базу, и всё сделанное в окне пропало бы при закрытии. Неизвестный аргумент – тоже код 2.

Демо-база (области «Дом» и «Работа», проект «Ремонт» с разделами, задачи на сегодня, вечер, со сроками) – из корня репозитория:

```sh
cargo build -p tally-cli -p tally-ui
scripts/seed-demo.sh /tmp/demo.db
TALLY_TODAY=2026-11-20 target/debug/tally-ui --db /tmp/demo.db
```

## Устройство

Логика окна – обычный Rust без Slint, с модульными тестами:

- `src/view.rs` – строки боковой панели и списка из снимка базы;
- `src/controller.rs` – состояние окна (выбранный список, задачи, закрытые в этом окне, сообщение) и решения по нажатиям;
- `src/keys.rs` – сочетания клавиш;
- `src/strings.rs` – общие строки интерфейса (даты – общие с консолью, `tally_client::show`).

Связь со Slint и системой:

- `src/backend.rs` – поток – владелец базы. Окно не ждёт базу: запрос уходит в поток через канал, ответ возвращается в поток окна через `slint::invoke_from_event_loop` и обратный вызов `poll`. В потоке – `tally_app::App` за интерфейсом `Service` (тем же, что у `tally_app::Worker`). Для тестов – `Inline`: тот же интерфейс, запрос выполняется сразу.
- `src/bind.rs`, `src/bind/` – перенос строк в модели Slint и обратные вызовы окна: карточка задачи, перетаскивание, проекты и области, повторы, поиск, настройки, быстрый ввод, напоминания, прокрутка.
- `src/desktop.rs`, `src/desktop/` – один оконный экземпляр на базу, трей, глобальная горячая клавиша, уведомления; запросы к экземпляру – `tally_client::desktop`.
- `ui/theme.slint` – тема: все цвета, шрифты и отступы в одном месте. `ui/icons.slint` – контурные значки. `ui/types.slint` – строки панели и списка. `ui/app.slint` – окно; `editor.slint`, `organization.slint`, `repeat.slint`, `settings.slint`, `drag.slint`, `desktop.slint` – карточка, проекты и области, повтор, настройки, перетаскивание, трей и быстрый ввод.
- Шрифт Inter v4.1 встроен (общая папка `assets/fonts` в корне, лицензия SIL OFL 1.1 – `assets/fonts/Inter-LICENSE.txt`).
- Значок приложения – `assets/icon.png`; из него `scripts/make-icons.py` делает `icon-window.png` (окна, `Theme.app-icon`), `icon-tray.png` (трей) и `icon.ico` с размерами Windows 16, 20, 24, 32, 40, 48, 64, 96, 128 и 256 px (вшивается в exe скриптом `scripts/package-windows.ps1`). Все три файла лежат в репозитории.
- `src/taskbar.rs` – в Windows Slint ставит окну только маленький значок, а панель задач берёт большой. После каждого показа окна модуль выставляет оба: берёт из значка в exe кадр под масштаб экрана (16 и 32 px при 100 %, 20 и 40 при 125 % и так далее); в сборке без значка в exe (`cargo run`) – картинку `Theme.app-icon`.
- В Windows `main.rs` собирается с подсистемой `windows`: при двойном щелчке консоль не открывается.

Интерфейс только на русском; строки собраны в одном месте. В окне нет подсказок – они в [руководстве](../../docs/user-guide.md). Вместо длинного тире в интерфейсе – «–».

## Тесты

```sh
cargo test -p tally-ui
```

- Без окна: `view.rs` (боковая панель и страницы из снимка), `controller.rs` (отметка, отмена и повтор, сообщения, общая с консолью база), `checkbox_rules.rs` и `checkbox_f5_and_history.rs` (правила отметок и клавиша F5).
- Остальные файлы поднимают окно Slint на тестовой платформе (`i-slint-backend-testing`, без экрана): щелчки, клавиши, доступность. Платформу можно включить один раз на процесс, поэтому каждый такой файл – отдельный тестовый процесс, и объединять их нельзя. Элементы ищутся по доступным именам, поэтому отладочная сборка `.slint` идёт с отладочными сведениями Slint (`build.rs`).
- По темам: `window*.rs` – сквозные сценарии окна; `stale_checkbox` (отметки), `editor_*` (карточка), `project_*` и `reopen_*` (проекты и повторное открытие), `drag_*` (перетаскивание), `search_*` (быстрый поиск и теги), `settings` (настройки и импорт), `desktop*` (быстрый ввод, напоминания, оконный экземпляр).
- Общее для тестов – `tests/common/`: демо-база через команды `tally-app`, помощники для окна.
