# Архитектура

Tally – cargo workspace из небольших крейтов («кубиков»). Каждая часть логики живёт в своём крейте и тестируется отдельно, интерфейс только показывает то, что посчитано ниже.

```
 tally-ui    tally-cli        программы: окно и консоль
       \      /
      tally-client            общее для обеих программ
           │
       tally-app              команды, журнал, отмена и повтор
        /     \
 tally-store  tally-when      база · разбор дат
        \     /
       tally-core ── tally-rank   модель и правила · ключи порядка
```

Окно и консоль не зависят друг от друга: общее вынесено в `tally-client`.

| Крейт | Назначение |
|---|---|
| [`tally-core`](../crates/tally-core/README.md) | Модели и правила списков, без ввода-вывода и без `now()` |
| `tally-rank` | Строковые ключи порядка (в духе LexoRank) |
| [`tally-when`](../crates/tally-when/README.md) | Разбор дат по-русски: «завтра», «пт», «через 3 дня», «вечером» |
| [`tally-store`](../crates/tally-store/README.md) | SQLite, миграции, репозиторий, нормализованный поиск, копии базы |
| [`tally-app`](../crates/tally-app/README.md) | Команды, журнал действий с отменой и повтором, поток – владелец базы |
| [`tally-client`](../crates/tally-client/README.md) | Общее для консоли и окна: путь к базе, сегодняшний день, русские даты, обмен с оконным процессом |
| [`tally-cli`](../crates/tally-cli/README.md) | Консольная программа `tally` |
| [`tally-ui`](../crates/tally-ui/README.md) | Окно `tally-ui` на Slint: только отображение и привязка к `tally-app` |

Правило: логика не живёт ни в `.slint`, ни в `main.rs` – только в `tally-app` и ниже.

## Модель «когда»

Вместо одного поля «когда» – три независимых:

- `start: Start` – `Inbox | Anytime | Someday`;
- `date: Option<Date>` – дата начала, в базе текст `YYYY-MM-DD`;
- `evening: bool` – блок «Вечер» в «Сегодня».

Отдельно – `deadline: Option<Date>`. «Сегодня» и «Планы» не хранятся, а вычисляются функциями вида `fn list_of(task, today: Date) -> List`. В ядре нет `now()`: сегодняшняя дата всегда параметр, поэтому смену суток при открытом приложении проверяют подстановкой другой даты. Правила списков – в [`tally-core`](../crates/tally-core/README.md).

## Порядок

У задачи два ключа: `index` (порядок внутри проекта или списка) и `today_index` (свой порядок в «Сегодня»), как в Things. Ключи – строки (`tally-rank`): между любыми двумя ключами всегда можно вставить новый, без предела точности `f64`. Ребалансировка – редкая операция.

## Поиск и кириллица

`LIKE` и `lower()` в SQLite нечувствительны к регистру только для ASCII. Поэтому колонка `search_text` хранит нормализованный текст (Unicode lowercase, `ё` → `е`, без лишних пробелов) и заполняется из Rust при каждой записи. Поиск идёт по ней; при росте объёма поверх неё можно добавить FTS5.

## Готовность к синхронизации

У каждой записи есть `uuid`, `created_at`, `updated_at` и `deleted_at` (мягкое удаление). Поля повторов (`repeat_rule`, `repeat_from`: по дате или после выполнения) – в схеме. Самой синхронизации между устройствами нет.

## Команды, журнал и потоки

- Все изменения – значения `Command` (`AddTask`, `Close`, `MoveTask`, `Undo`, …). Команда выполняется в одной транзакции записи вместе со строкой журнала действий.
- Журнал хранится в базе и общий для всех клиентов: `Ctrl+Z` в окне отменяет и действие, сделанное в `tally`. Отмена возвращает записи в сохранённое состояние «до», повтор – в «после»; перед записью каждая запись сверяется, и если её изменили в обход журнала, отмена отклоняется (подробности – в [`tally-app`](../crates/tally-app/README.md)).
- Одна схема для всего: один поток владеет соединением с базой, остальные (окно, напоминания, быстрый ввод) шлют ему сообщения через канал. Интерфейс `Service` один для синхронного `App` и потока `Worker`; консоль вызывает `execute` напрямую.
- Окно не ждёт базу: запрос уходит в поток, ответ приходит через `slint::invoke_from_event_loop`.

## Стек

| Задача | Крейт |
|---|---|
| Интерфейс | `slint` 1.19, рендерер Skia по умолчанию, femtovg – запасная фича |
| База | `rusqlite` (bundled SQLite, API резервного копирования) |
| Идентификаторы | `uuid` |
| Даты | `jiff`; в базе текст `YYYY-MM-DD` |
| Ошибки | `thiserror` в библиотеках, `anyhow` в программах |
| Консоль | `clap` |
| Сериализация | `serde`, `serde_json` (журнал, обмен с окном, импорт и экспорт) |
| Уведомления, горячая клавиша | `notify-rust`, `global-hotkey` (Windows, macOS, Linux X11; на Wayland – команда `tally quick-add`) |
| Трей | встроенный `system-tray` Slint |
| Пути | `directories` |
| Шрифт | Inter, встроен – одинаковый вид и кириллица на всех ОС |
| Тесты | `proptest`, `assert_cmd`, `tempfile`, тестовая платформа Slint |

## Проверки

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Тех же проверок ждёт CI (`.github/workflows/ci.yml`): Linux, Windows и macOS, плюс сборка с рендерером femtovg. В Linux для сборки нужны `libfontconfig1-dev`, `libfreetype6-dev` и обычные библиотеки X11/Wayland (список – в workflow).
